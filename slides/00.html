About the book

The book at a glance

  • Sequential Decision Analytics and Modeling (2e), Warren B. Powell (February 2026), subtitle: Modeling with Python

  • Sequential decision problems always look like this:

    decision, information, decision, information, decision, …

  • Each decision brings a cost or reward, and decisions are made with a method called a policy

  • Central goal: design policies that work well over time, under uncertainty about information that has not arrived yet

  • Examples are “the mathematics of everyday life”: selling an asset, inventories, routes, drug testing, ads, supply chains

  • Goal: learn how to think about these problems, even if you never write a line of code

Who is it for?

  • Aimed at undergraduate or master’s students who have taken a course in probability and statistics
  • No linear programming needed (one example, blood management, uses it)
  • Teach-by-example style: every chapter is built around a specific problem
  • Chapters 2-6 and 8-14 follow the same outline, so they can be read in any order
  • Optional reference for more depth: Powell’s graduate text Reinforcement Learning and Stochastic Optimization (tinyurl.com/RLandSO)

How the book is organized

Part Chapters What happens

Simple examples 2-6 One problem per chapter, chosen to bring out the four classes of policies

The two big ideas (Chapter 1)

Five elements of every sequential decision model

  1. State variables \(S_t\) (physical, information and belief state)
  2. Decision variables \(x_t\)
  3. Exogenous information \(W_{t+1}\)
  4. Transition function \(S^M(S_t, x_t, W_{t+1})\)
  5. Objective function

Four classes of policies (they cover any method for making decisions)

  • Policy search: PFA (policy function approximations), CFA (cost function approximations)
  • Lookahead: VFA (value function approximations), DLA (direct lookahead approximations)

Exercises and companion Python code

  • Each chapter closes with three kinds of exercises:
    • Review questions: reinforce the basics
    • Problem-solving questions: modeling challenges
    • Programming questions: use the book’s Python modules, sometimes modifying the code
  • The library (rewritten for Python 3 by Prof. Dennis Djanka, including Jupyter notebooks for some problems) is at tinyurl.com/sdagithub
  • Modules named in the exercises: AssetSelling (ch. 2), AdaptiveMarketPlanning (ch. 3), StochasticShortestPath Static and Dynamic (ch. 5-6), EnergyStorage I (ch. 8), TwoNewsvendor (ch. 10), BloodManagement (ch. 13), ClinicalTrials (ch. 14)
  • Also useful: supplementary material and Powell’s undergraduate course slides for this book

Chapters 1, 7, 9, 11 and 12 do not name a Python module in their exercises. Chapter 4’s programming exercises name AdaptiveMarketPlanning in the text, which looks like a copy-paste slip (the preface lists a diabetes module). Check the repository for exact file names.

How to present

Want to present a chapter?

  1. Open the Cohort 1 sign-up sheet (also pinned in Slack)
  2. Put your name next to a chapter and date
  3. Prepare your slides (next slides explain how)

Presenting is how you learn. Ángel is happy to help you through the process.

Overview: slides are code

  • Every deck is a .qmd file in slides/ (slides/03.qmd = chapter 3)
  • The site is a Quarto website, hosted on GitHub
  • Your slides reach the site through a pull request (PR)
  • Once the PR is merged, the site rebuilds automatically

Full instructions: the GitHub repo README

One-time setup

  1. Install git and an editor (RStudio/Positron for R, VS Code for Python)
  2. Fork and clone the repo
    • R: usethis::create_from_github("AngelFelizR/bookclub-sdamodeling")
    • git: click Fork on GitHub, then git clone
  3. Install R packages with pak::pak()
    • Required even for Python slides: Quarto runs an R script before every render
  4. Python slides only: install Python 3.11+, then pip install jupyter ipykernel and pip install .

Each time you present

  1. Create a branch (usethis::pr_init("chapter-3") or git switch -c chapter-3)
  2. Edit slides/NN.qmd (# = section, ## = slide)
  3. Add the packages you used
  4. Preview: Ctrl/Cmd-Shift-K or quarto preview slides/NN.qmd
  5. Commit your changes
  6. Push and open a PR (usethis::pr_push() or git push -u origin chapter-3)
  7. After merge, clean up (usethis::pr_finish() or delete the branch)

R or Python?

  • R: no special header; add packages with usethis::use_package("pkg")
  • Python: start the file with engine: jupyter; list packages in pyproject.toml
  • You can mix: the engine is chosen per file
  • The book’s own code is in Python, but your slides can use either language

Ground rules

  • main is protected: nobody pushes directly, everything goes through a PR
  • A PR must pass its automated checks before merging
  • Stuck? Ask in Slack

Learning objectives (LOs)
